  service    handler work only. A closed-loop benchmark reports this,
             and a stall cannot move it: while the system is frozen it
             takes no samples.
  corrected  service with the coordinated-omission correction applied
             against the expected inter-tick interval.
  response   measured from when each tick was DUE. Exact, because the
             replay knows its own schedule.
  queueing   response minus service: time a tick spent already late.
  host floor CONTROL. The same schedule with no pipeline attached, so this
             is the machine's own lateness. Response figures at or below

  Accelerating the tape by S is asking the pipeline to handle a market
  S times busier with the same burst structure. Read down the table:
  service p99 barely moves -- the handler's own work does not depend on
  how fast ticks arrive -- while response p99 climbs without bound once
  arrivals outpace it. A benchmark reporting only the first column would
  show a system with no saturation point at all.
